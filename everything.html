🔐 Two CPU modes User applications run in user mode and cannot touch hardware directly. Privileged instructions only run in kernel mode — trying them from user mode triggers a trap.
📞 System calls When an app needs a file, memory or device, it makes a system call. This switches context into the kernel, executes the request, then returns control to the app.
🧱 Hardware abstraction Because the OS hides device details, the same program can run on very different hardware without being rewritten.

Exhibit 03

Why We Need an OS

Without one, every program would have to speak directly to the hardware — and only one could run at a time.

Without an operating system

  • Each program must directly control the hardware itself
  • No sharing of resources — one computer, one job
  • No protection between different applications
  • Programming becomes extremely complex
  • Changing behaviour meant physically rewiring the machine

With an operating system

  • Hardware abstraction simplifies programming
  • Resource sharing enables multitasking
  • Security and protection between programs
  • Standardised interfaces for developers
  • Programs can be loaded, run and swapped without rewiring

Exhibit 04

A Short History

From rewiring machines by hand to running an entire cloud — the OS has come a long way.

1940s – 1950s

Programs on bare hardware

Programs ran directly on the machine, one job at a time. Changing a program often meant rewiring the computer.

1960s

Batch processing

First simple operating systems managed queues of jobs fed in from punched cards. IBM's System/360 was the first family of compatible computers with a common OS.

1970s

Time-sharing & UNIX

Multiple users shared one machine, each getting a slice of CPU time. UNIX was developed and became the foundation for many modern systems.

1980s

Personal computers

MS-DOS and early Windows brought computing to individuals. User-friendly interfaces and multitasking began to appear.

1990s

GUIs become standard

Graphical user interfaces replaced command lines for everyday users. Windows 95, macOS and Linux desktops flourished.

2000s

Mobile operating systems

iOS and Android arrived, designed for touch, battery life and limited resources. Mobile OS design emphasised efficiency and responsiveness.

2000s – today

Cloud & distributed systems

Operating systems now power data centres, virtual machines, containers and billions of connected devices.

Exhibit 05

Types of Operating Systems

Not every OS is built for a desktop. The job dictates the design.

💻

General-purpose

Runs many applications on a wide range of hardware. Supports multitasking and a broad selection of software.

Windows · macOS · Linux
📱

Mobile

Built for phones and tablets — limited resources, touch input, efficient power use and responsive performance.

iOS · Android
🔧

Embedded

Dedicated devices that do one main job, often with tight limits on power, size and memory.

Embedded Linux · ATMs · IoT
🌐

Network

Specialised for communication between devices on a LAN — handling protocols, packets and routing.

Cisco IOS · RouterOS · ZyNOS
⏱️

Real-time

Guarantees predictable timing for tasks with strict deadlines — essential in critical systems.

FreeRTOS · VxWorks
